# 现货交易与合约交易业务详解

> 版本：v1.0  
> 日期：2026-05-09  
> 关联项目：ArkHub 加密货币/NFT 综合交易平台

---

## 1. 核心概念对比

| 维度 | 现货交易（Spot Trading） | 合约交易（Futures Trading） |
|------|------------------------|--------------------------|
| **买了什么** | 真实的加密货币（BTC、ETH 等） | 一份"赌约"（做多/做空合约） |
| **资产所有权** | ✅ 买入后真的拥有币 | ❌ 没有币，只有合约仓位 |
| **杠杆** | 无杠杆（1倍） | 10x、50x、100x 可选 |
| **最大亏损** | 币价归零，亏光本金 | 可能爆仓，本金清零 |
| **盈利来源** | 币价上涨 | 价格波动差价（可做多也可做空） |
| **交割** | 即时（T+0） | 永续合约永不交割，定期结算 |
| **提现** | 提真实的币到钱包 | 只能提 USDT（没有币） |
| **风险等级** | ⭐⭐⭐ 中等 | ⭐⭐⭐⭐⭐ 极高 |

**一句话理解：**

> **现货 = 买真币，买了币就是你的，可以提到钱包。**
> **合约 = 赌涨跌，不碰真币，赌对了赚 USDT，赌错了爆仓。**

## 2. 现货交易完整流程

### 2.1 流程总览

```
充值 USDT（链上）
    ↓
下单买 BTC（用 USDT 换 BTC）
    ↓
撮合成交（内部记账）
    ↓
你的账户：USDT 减少，BTC 增加（真实资产）
    ↓
提现 BTC 到钱包（链上转账）
    ↓
钱包里收到真币
```

### 2.2 详细步骤

#### 步骤 1：充值（链上操作）

| 项目 | 说明 |
|------|------|
| **操作** | 用户把 USDT 从个人钱包转到交易所地址 |
| **链上确认** | 等待 6-12 个区块确认（约 2-3 分钟） |
| **交易所处理** | 监听到账 → 查地址归属 → 更新数据库余额 |
| **结果** | 用户账户显示 +1000 USDT |

```
用户钱包 ──链上转账──→ 交易所地址 ──确认──→ 交易所数据库更新
```

#### 步骤 2：下单（内部操作）

| 项目 | 说明 |
|------|------|
| **操作** | 用户选择 BTC/USDT 交易对，输入价格和数量 |
| **订单类型** | 限价单、市价单、止损单 |
| **风控校验** | 余额是否充足、价格合法性、异常拦截 |
| **结果** | 订单进入订单簿，等待撮合 |

#### 步骤 3：撮合（内部操作，10ms）

| 项目 | 说明 |
|------|------|
| **撮合原则** | 价格优先、时间优先 |
| **技术实现** | Disruptor 无锁环形队列 + 内存订单簿 |
| **性能指标** | 撮合延迟 < 10ms，TPS 百万级 |
| **结果** | 生成成交记录，双方资产实时变动 |

#### 步骤 4：成交（内部记账）

**用户买 BTC：**
```
成交前：
  用户账户：1000 USDT，0 BTC

成交（买 0.01 BTC @ 50000 USDT）：
  用户账户：500 USDT，0.01 BTC
  （没有链上交易！只是数据库更新）
```

#### 步骤 5：提现（链上操作）

| 项目 | 说明 |
|------|------|
| **操作** | 用户填写提现地址，提交提现申请 |
| **风控审核** | 大额需人工审核，AML 检查 |
| **链上转账** | 交易所从热钱包/冷钱包转账到用户地址 |
| **结果** | 用户钱包收到真实的 BTC |

## 3. 合约交易完整流程

### 3.1 流程总览

```
充值 USDT（链上）
    ↓
划转保证金（内部转账）
    ↓
开仓（买入赌约：做多/做空 + 杠杆倍数）
    ↓
持仓监控（实时对比指数价格，计算盈亏）
    ↓
平仓或爆仓（内部结算）
    ↓
盈亏 USDT 回到账户
    ↓
提现 USDT（链上转账）
```

### 3.2 详细步骤

#### 步骤 1：充值（同现货）

用户充值 1000 USDT 到交易所。

#### 步骤 2：划转保证金

| 项目 | 说明 |
|------|------|
| **操作** | 用户将资金从"现货账户"划转到"合约账户" |
| **本质** | 内部转账，冻结保证金 |
| **结果** | 合约账户显示 1000 USDT 可用保证金 |

#### 步骤 3：开仓（买入赌约）

| 项目 | 说明 |
|------|------|
| **操作** | 用户选择做多/做空、杠杆倍数、仓位大小 |
| **保证金占用** | 1000 USDT（假设 10x 杠杆，仓位价值 10000 USDT） |
| **账户变化** | 保证金被冻结，生成合约仓位 |
| **是否有真币** | ❌ 没有！只有一份"赌约" |

**合约仓位示例：**
```
合约ID: #12345
方向: 做多（赌涨）
杠杆: 10x
保证金: 1000 USDT
开仓价: 50000 USDT/BTC
仓位价值: 10000 USDT（0.2 BTC）
```

#### 步骤 4：持仓监控（实时计算）

```
┌─────────────────────────────────────────┐
│           价格监控循环（每毫秒）            │
│                                         │
│  ① 行情聚合引擎采集 14+ 交易所现货价格     │
│           ↓                             │
│  ② 计算指数价格（加权平均 + 滤波算法）      │
│           ↓                             │
│  ③ 对比用户持仓的开仓价                   │
│           ↓                             │
│  ④ 计算未实现盈亏（浮动盈亏）             │
│           ↓                             │
│  ⑤ 检查保证金率，是否触发强平             │
└─────────────────────────────────────────┘
```

**盈亏计算：**

| 当前 BTC 价格 | 价格变动 | 实际盈亏 | 保证金率 | 状态 |
|-------------|---------|---------|---------|------|
| 50000 | 0% | 0 | 10% | 正常 |
| 55000 | +10% | +1000 USDT | 变高 | 盈利，可平仓 |
| 45000 | -10% | -1000 USDT | 接近0 | 接近爆仓 |
| 47500 | -5% | -500 USDT | 5% | 警戒线 |

#### 步骤 5：平仓或爆仓

**主动平仓（止盈/止损）：**
```
用户点击"平仓"
    ↓
系统计算盈亏
    ↓
解除保证金冻结
    ↓
盈亏 USDT 回到可用余额
    ↓
合约仓位消失
```

**爆仓（强制平仓）：**
```
保证金率 < 维持保证金率
    ↓
系统强制平仓
    ↓
保证金清零（或部分亏损）
    ↓
合约仓位消失
    ↓
若穿仓：风险准备金垫付或社会化分摊
```

## 4. 现货 vs 合约：核心差异图解

### 4.1 资产所有权

```
┌─────────────────────────────────────┐
│  现货交易                             │
│  你的账户：1000 USDT + 0.01 BTC      │
│       ↑                               │
│  【真的有 BTC！】                      │
│       ↓                               │
│  可以提现到钱包                        │
└─────────────────────────────────────┘

┌─────────────────────────────────────┐
│  合约交易                             │
│  你的账户：1000 USDT + 一份赌约        │
│       ↑                               │
│  【没有 BTC，只有赌约】                 │
│       ↓                               │
│  不能提 BTC，只能提 USDT              │
└─────────────────────────────────────┘
```

### 4.2 数据流向对比

**现货交易：**
```
充值 ──链上──→ 内部余额 ──内部撮合──→ BTC持仓 ──提现──链上──→ 钱包

链上：充值、提现（2次）
内部：下单、撮合、持仓更新（无数次）
```

**合约交易：**
```
充值 ──链上──→ 保证金 ──内部开仓──→ 持仓监控 ──平仓结算
                                        │
                                        ├─ 正常：内部结算
                                        │
                                        ├─ 爆仓：内部强平
                                        │       若穿仓：链上回补
                                        │
                                        └─ 预言机价格：EIP-712上链

链上：充值、预言机价格、提现（3次）
内部：开仓、平仓、资金费率（无数次）
```

## 5. 关键业务问题解答

### 5.1 为什么合约交易不碰真币？

> **因为合约本质是"对赌"，不是买卖。**

你签的是一份合同："我赌 BTC 会涨/跌，如果我赌对了，对方赔我钱；如果我赌错了，我赔给对方钱。"

整个过程中：
- ❌ 你没有买 BTC
- ❌ 你没有卖 BTC
- ✅ 你只是用 USDT 做保证金，赌价格涨跌

### 5.2 合约的价格怎么来？

> **合约价格必须锚定现货价格。**

平台聚合 14+ 家交易所的现货价格 → 中位数滤波 → 异常剔除 → 加权计算 → 得到**指数价格**。

合约的撮合、爆仓判断、盈亏计算，都以这个**指数价格**为准。

如果合约价格脱离现货，就会被操纵，用户会不公平地爆仓。

### 5.3 为什么合约要加杠杆？

| 杠杆 | 投入 | 仓位价值 | 价格上涨 10% | 收益 |
|------|------|---------|-------------|------|
| 1x（现货） | 1000 USDT | 1000 USDT | +100 USDT | 10% |
| 10x | 1000 USDT | 10000 USDT | +1000 USDT | 100% |
| 50x | 1000 USDT | 50000 USDT | +5000 USDT | 500% |
| 100x | 1000 USDT | 100000 USDT | +10000 USDT | 1000% |

**杠杆放大了收益，也放大了风险。**

### 5.4 爆仓是怎么回事？

```
保证金 1000 USDT，10x 杠杆
    ↓
BTC 价格从 50000 跌到 45000（-10%）
    ↓
由于 10x 杠杆，实际亏损 = -10% x 10 = -100%
    ↓
保证金亏光（1000 USDT）
    ↓
触发爆仓，系统强制平仓
    ↓
仓位清零，保证金归零
```

**爆仓 = 保证金亏光，系统自动帮你"止损"。**

### 5.5 提现时有什么区别？

| 场景 | 现货 | 合约 |
|------|------|------|
| **账户里有** | USDT + BTC | USDT（只有 USDT） |
| **提现选择** | 提 USDT 或提 BTC | 只能提 USDT |
| **链上操作** | 转 USDT 或转 BTC | 转 USDT |
| **钱包收到** | USDT 或真 BTC | USDT（不是 BTC） |

## 6. 中心化交易所的信任风险

### 6.1 核心风险

无论是现货还是合约，**撮合和持仓都是交易所内部记账**。

```
交易所数据库：
┌────────┬─────────────┬─────────┬─────────┐
│ user   │ usdt_balance│ btc_bal │ pos_usd │
├────────┼─────────────┼─────────┼─────────┤
│  luca  │   500.00    │  0.01   │  10000  │
└────────┴─────────────┴─────────┴─────────┘
         ↑
    这只是数据库里的数字！
```

### 6.2 主要风险类型

| 风险 | 说明 | 案例 |
|------|------|------|
| **交易所跑路** | 平台关闭，用户资产无法取出 | FTX（2022） |
| **内部挪用** | 管理员修改数据库，挪用用户资产 | Mt.Gox（2014） |
| **黑客攻击** | 攻破数据库或钱包，盗取资产 | Coincheck（2018） |
| **数据丢失** | 数据库损坏，无法恢复 | 各种小交易所 |

### 6.3 用户的自我保护

> **Not Your Keys, Not Your Coins.**

| 存放位置 | 安全性 | 建议 |
|---------|--------|------|
| 个人钱包（Ledger/MetaMask） | ⭐⭐⭐⭐⭐ | 长期持有、大额资产 |
| 交易所 | ⭐⭐⭐ | 交易时使用，交易完提走 |

**铁律：**
- 小额在交易所交易
- 大额提到自己钱包
- 不要长期把资产放在交易所

## 7. 总结

| 问题 | 现货 | 合约 |
|------|------|------|
| **本质** | 买真币 | 赌涨跌 |
| **买了什么** | 真实的 BTC/ETH | 一份赌约 |
| **有币吗** | ✅ 有真币 | ❌ 没有币 |
| **能提币吗** | ✅ 能提 BTC | ❌ 只能提 USDT |
| **赚钱方式** | 币价上涨 | 价格波动（可做多做空） |
| **风险** | 币价归零 | 爆仓清零 |
| **链上环节** | 充值、提现 | 充值、预言机、提现 |
| **撮合方式** | 内部撮合，即时成交 | 内部撮合，即时成交 |

**一句话总结：**

> **现货 = 真金白银买币，买了就是你的。**
> **合约 = 用 USDT 做押金，赌价格涨跌，没有真币。**

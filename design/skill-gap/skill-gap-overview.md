> 版本：v1.0
> 日期：2026-05-09
> 对比对象：web3-go 学习计划 vs ArkHub 项目需求

---

## 1. 背景说明

### web3-go 学习计划

一个为期 4 周的 Go + Web3 后端学习计划，目标是从零建立 Go 语言 + Ethereum 基础设施开发能力。

| 周次 | 主题 | 核心产出 |
|------|------|---------|
| **Week 1** | Go 语法脱敏 + 标准库 | HTTP Client、依赖注入、goroutine、channel、连接池、单元测试 |
| **Week 2** | Ethereum RPC 实战 | 连接节点、查询余额、交易解析、事件订阅、发送交易、多链客户端 |
| **Week 3** | 事件监听 + 并发索引器 | errgroup 并发扫块、事件解析、断点续扫、链重组检测、Gin API |
| **Week 4** | 多链 EVM 索引器 | REST API、GraphQL、Docker、pgx、多链 Worker Pool |

### ArkHub 项目需求

一个面向**现货、合约、NFT 交易的综合性数字资产金融平台**，技术栈涵盖高并发撮合、多源行情聚合、链上链下一致性、NFT 风控、回购统计等。

| 核心能力 | 技术点 |
|---------|--------|
| **高并发低延迟** | Disruptor 无锁队列、内存订单簿、红黑树、百万级 TPS |
| **行情聚合** | 14 路异构行情源、中位数滤波、异常剔除、加权融合 |
| **链上链下一致** | 双源校验、异步补偿、事件监听、断点续扫 |
| **NFT 业务** | IPFS 元数据、稀有度计算、热度评分、异常交易检测 |
| **回购统计** | 定时聚合、Redis 缓存、降级策略 |
| **风控服务** | 实时风控模型、异常检测、动态热点管理 |
| **基础设施** | Docker/K8s、Nacos、Prometheus、RocketMQ |

## 6. 核心差距总结

### 6.1 完全缺失的领域（优先级 P0）

1. **高并发系统设计**：Disruptor 模式、无锁队列、内存订单簿
2. **消息队列**：RocketMQ/Kafka 的生产消费模型、Topic 设计、消息可靠性
3. **API Gateway**：路由分发、JWT 鉴权、限流熔断、WebSocket Gateway
4. **分布式缓存**：Redis 分布式锁、缓存穿透/击穿/雪崩防护
5. **监控告警**：Prometheus 指标采集、Grafana 仪表盘、告警规则

### 6.2 需要深入的领域（优先级 P1）

1. **并发编程**：从基础 goroutine 到无锁并发、CAS、内存模型
2. **数据结构**：红黑树、跳表、环形队列等高级数据结构
3. **多链适配**：从基础多链客户端到策略模式、统一 SDK
4. **Docker/K8s**：从基础容器化到 K8s 编排、Ingress、Service Mesh

### 6.3 锦上添花的领域（优先级 P2）

1. **智能合约高级**：EIP-712 签名、预言机机制
2. **风控算法**：异常检测、评分模型、规则引擎
3. **IPFS**：元数据拉取、分布式存储
4. **数据聚合**：定时任务、预聚合、增量计算

## 7. 学习路径建议

### 第一阶段：基础补齐（1-2 周）

- [ ] Redis 高级应用（分布式锁、缓存策略）
- [ ] 消息队列基础（RocketMQ 或 Kafka）
- [ ] API Gateway 设计（Nginx + Go 实现）

### 第二阶段：核心攻坚（2-3 周）

- [ ] 高并发系统设计（Disruptor、无锁队列）
- [ ] 内存数据结构（红黑树、跳表实现）
- [ ] 微服务基础设施（Nacos、Prometheus、Grafana）

### 第三阶段：业务深入（2 周）

- [ ] 行情聚合算法（滤波、异常剔除、加权融合）
- [ ] 风控模型（异常检测、评分算法）
- [ ] EIP-712 签名与预言机

### 第四阶段：实战整合（1-2 周）

- [ ] 按阶段实现 ArkHub 各模块
- [ ] 编写单元测试、集成测试
- [ ] Docker Compose 一键部署

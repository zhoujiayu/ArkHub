## 1. 什么是现货交易

**现货交易（Spot Trading）** 指买卖双方在达成交易后，资产立即或极短时间内完成交割的交易方式。在 Web3 领域，即用户买入或卖出加密货币/NFT 后，资产所有权在交易完成瞬间发生转移。

> 核心特征：**一手交钱、一手交货，即时交割（T+0）**。

---

## 2. 现货 vs 合约的核心区别

| 维度 | 现货交易 | 合约交易（Futures） |
|------|---------|-------------------|
| **资产所有权** | 买入后真正持有资产 | 仅持有合约，不持有实物 |
| **交割时间** | 即时（T+0） | 未来约定时间或永续滚动 |
| **杠杆** | 无杠杆或低杠杆 | 高杠杆（10x - 100x） |
| **风险特征** | 资产涨跌风险 | 爆仓、资金费率、穿仓风险 |
| **交易对象** | BTC、ETH、EDGE 等代币本身 | 代币价格的未来预期 |
| **收益来源** | 资产升值 | 价格波动差价 |

> **一句话理解**：现货 = 买股票（真实持有）；合约 = 买期货（赌涨跌，不持有）。

## 3. 现货交易完整业务流程

### 3.1 流程总览

```
┌──────────┐     ┌──────────┐     ┌──────────┐     ┌──────────┐
│  用户    │────→│  交易所   │────→│  链上    │────→│  用户钱包 │
│ 下单买BTC │     │ 撮合成交  │     │ 资产划转  │     │ 收到BTC  │
└──────────┘     └──────────┘     └──────────┘     └──────────┘
```

### 3.2 详细步骤

#### 步骤 1：充值（Deposit）

| 项目 | 说明 |
|------|------|
| **触发条件** | 用户决定参与交易，需要先在平台拥有资金 |
| **操作** | 用户将 USDT/BTC/ETH 等资产从个人钱包转入交易所指定的充值地址 |
| **链上确认** | 交易所监听链上转账事件，等待区块确认（通常 6-12 个区块） |
| **到账处理** | 确认无误后，交易所更新用户账户余额，用户可在平台内使用 |
| **技术要点** | 多链充值支持、区块回滚防护、充值异常报警 |

```
用户钱包 ──链上转账──→ 交易所热钱包 ──确认──→ 用户账户余额 +100 USDT
```

#### 步骤 2：下单（Place Order）

| 项目 | 说明 |
|------|------|
| **触发条件** | 用户选择交易对（如 BTC/USDT），决定买入或卖出 |
| **订单类型** | 限价单（Limit）、市价单（Market）、止损单（Stop-loss）等 |
| **参数** | 方向（买入/卖出）、数量、价格（限价单）、有效期 |
| **风控校验** | 余额校验、价格合法性、异常下单拦截（高频、大单预警） |
| **落库** | 订单写入订单簿，等待撮合 |

```
用户 ──下单──→ 订单簿（Order Book）
       ├─ 限价单：挂到买卖盘对应价格档位
       └─ 市价单：直接匹配最优价格成交
```

#### 步骤 3：撮合（Matching）

| 项目 | 说明 |
|------|------|
| **触发条件** | 买单价格 ≥ 卖一价，或卖单价格 ≤ 买一价 |
| **撮合原则** | **价格优先、时间优先** |
| **撮合引擎** | Disruptor 无锁环形队列 + 内存订单簿，支撑百万级 TPS |
| **匹配过程** | 1. 新订单进入队列  <br> 2. 与订单簿对面最优价匹配  <br> 3. 生成成交记录  <br> 4. 未成交部分继续挂单 |
| **异常处理** | 极端行情自动熔断、价格保护、大单拆分 |

```
┌─────────────┐
│   买单队列   │
│ 100 USDT x2 │ ←──── 新市价单：买 1 BTC
│  99 USDT x5 │         匹配卖一价 100 USDT
└─────────────┘              ↓
                        ┌─────────────┐
                        │   卖单队列   │
                        │ 100 USDT x1 │ ←── 成交 1 BTC @ 100 USDT
                        │ 101 USDT x3 │      从卖单队列移除
                        └─────────────┘
```

#### 步骤 4：成交（Trade Execution）

| 项目 | 说明 |
|------|------|
| **触发条件** | 撮合引擎成功匹配买卖双方 |
| **资产变动** | 买方账户：-USDT，+BTC  <br> 卖方账户：+USDT，-BTC |
| **手续费扣除** | 按费率从成交方扣除手续费（通常用平台代币抵扣有优惠） |
| **成交记录** | 生成唯一 Trade ID，记录价格、数量、时间、对手方信息 |
| **持久化** | 异步写入数据库，保证数据不丢失 |

```
成交前：
  买方账户：1000 USDT, 0 BTC
  卖方账户：0 USDT, 5 BTC

成交后（买 1 BTC @ 100 USDT，手续费 0.1%）：
  买方账户：899.9 USDT, 1 BTC
  卖方账户：99.9 USDT, 4 BTC
  平台手续费：0.1 USDT
```

#### 步骤 5：结算（Settlement）

| 项目 | 说明 |
|------|------|
| **触发条件** | 成交完成后即时结算 |
| **结算内容** | 更新双方账户余额、生成账单、计算盈亏 |
| **对账机制** | 定时与链上余额对账，确保账实一致 |
| **异常补偿** | 发现差异时自动触发补偿逻辑 |

```
成交记录 ──→ 账户余额更新 ──→ 账单生成 ──→ 日终对账
                    │
                    ↓
               链上余额校验
               （双源校验机制）
```

#### 步骤 6：提现（Withdrawal）

| 项目 | 说明 |
|------|------|
| **触发条件** | 用户将平台内资产提取到个人钱包 |
| **操作** | 用户填写提现地址、数量，提交申请 |
| **风控校验** | 地址白名单、大额提现人工审核、反洗钱（AML）检查 |
| **链上转账** | 交易所从热钱包或冷钱包转账到用户指定地址 |
| **到账确认** | 用户钱包收到资产，交易完成 |

```
用户账户 ──提现申请──→ 风控审核 ──通过──→ 交易所钱包 ──链上转账──→ 用户钱包
              │
              └─ 拒绝 → 返回用户，记录原因
```

## 4. 现货交易在平台中的角色

### 4.1 独立业务线

现货交易是平台的核心业务之一，为用户提供：

- **币币交易**：BTC/USDT、ETH/USDT、EDGE/USDT 等交易对
- **NFT 交易**：NFT 资产的买卖流转
- **法币通道**：部分平台支持法币直接购买加密货币（需合规牌照）

### 4.2 合约交易的价格锚点

现货价格是合约指数价格的重要构成：

```
┌─────────────────────────────────────────────────────────┐
│                     行情聚合引擎                          │
│  ┌──────────┐  ┌──────────┐  ┌──────────┐  ┌──────────┐ │
│  │ 交易所 A  │  │ 交易所 B  │  │ 交易所 C  │  │ 平台现货  │ │
│  │ BTC/USDT │  │ BTC/USDT │  │ BTC/USDT │  │ BTC/USDT │ │
│  └────┬─────┘  └────┬─────┘  └────┬─────┘  └────┬─────┘ │
│       │             │             │             │       │
│       └─────────────┴─────────────┴─────────────┘       │
│                           ↓                               │
│                   中位数滤波 + 异常剔除                      │
│                           ↓                               │
│                    加权融合计算                             │
│                           ↓                               │
│                    合约指数价格                             │
└─────────────────────────────────────────────────────────┘
```

- 合约的**标记价格（Mark Price）**和**指数价格（Index Price）**需要参考真实现货成交价
- 脱离现货价格，合约将失去锚定，容易被操纵
- 平台将自有现货价格纳入聚合，提升合约价格准确性

## 5. 技术实现要点

### 5.1 高并发撮合

| 技术点 | 实现方案 | 效果 |
|--------|---------|------|
| 订单接收 | Disruptor 无锁环形队列 | 避免锁竞争，支撑百万级 TPS |
| 订单簿 | 内存数据库（Go map + 红黑树） | 撮合延迟 < 10ms |
| 撮合算法 | 价格优先 + 时间优先 | 公平高效 |
| 熔断机制 | Sentinel / 自研熔断器 | 极端行情 0 崩溃 |

### 5.2 资金安全

| 技术点 | 实现方案 |
|--------|---------|
| 冷热钱包分离 | 热钱包用于日常提现，冷钱包离线存储大额资产 |
| 多重签名 | 提现需多把私钥签名，单点无法盗用 |
| 链上监听 | 实时监控充值、提现状态，异常即时报警 |
| 双源校验 | 核心业务操作前实时调用链上 API 校验状态 |

### 5.3 性能指标

| 指标 | 目标值 |
|------|--------|
| 撮合延迟 | < 10ms |
| 订单吞吐 | 百万级 TPS |
| 充值确认 | 12 个区块内到账 |
| 提现处理 | 审核通过后 30 分钟内到账 |
| 系统可用性 | 99.99% |

## 6. 现货交易 vs 合约交易业务对比

| 对比维度 | 现货交易 | 合约交易 |
|---------|---------|---------|
| **用户画像** | 长期持有者、价值投资者 | 投机者、对冲者、套利者 |
| **盈利模式** | 资产升值、理财收益 | 价格波动差价、资金费率套利 |
| **风险等级** | 中（资产波动） | 高（爆仓、穿仓） |
| **入门门槛** | 低（买币即持有） | 高（需理解杠杆、保证金、强平） |
| **平台收入** | 交易手续费、提现手续费 | 交易手续费、资金费率、爆仓穿仓收益 |
| **技术挑战** | 撮合性能、资金安全 | 风险引擎、价格锚定、爆仓清算 |

---

## 7. 总结

Web3 现货交易是整个交易平台的**基石业务**，它的核心特征是**即时交割、真实资产转移**。在技术实现上，对**撮合性能**和**资金安全**要求极高，同时为合约交易提供**价格锚定**。

在 ArkHub 项目中，现货交易不仅是一条独立的业务线，更是保障合约价格准确性的关键数据来源。平台通过聚合 14+ 家交易所和自有现货价格，经中位数滤波和异常剔除算法处理，输出精准的指数价格，支撑百万级用户的合约交易需求。

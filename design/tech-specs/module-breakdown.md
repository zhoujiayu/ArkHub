# ArkHub 平台 — 模块拆分总览

> 版本：v1.0
> 日期：2026-05-09
> 作者：系统架构组

---

## 设计原则

1. **渐进式开发**：每个阶段完成后，项目可独立运行并验证
2. **自底向上**：从基础设施到业务层，逐层构建
3. **模块解耦**：各阶段通过标准接口（HTTP/REST、gRPC、MQ）通信，降低耦合
4. **可验证性**：每个阶段提供独立验证方式（API测试、单元测试、集成测试）

---

## 阶段总览

| 阶段 | 模块名称 | 可验证产出 | 预计工期 | 依赖阶段 |
|------|---------|-----------|---------|---------|
| **阶段一** | 基础设施层 | Docker Compose 一键启动，健康检查通过 | 3 天 | 无 |
| **阶段二** | 网关层与基础服务 | API Gateway 路由转发、JWT 鉴权、限流熔断 | 5 天 | 阶段一 |
| **阶段三** | 行情聚合服务 | 模拟 3 路行情源，聚合后输出指数价格 | 7 天 | 阶段一 |
| **阶段四** | 订单撮合引擎 | 模拟下单、撮合、成交，验证百万级吞吐 | 10 天 | 阶段一、阶段二 |
| **阶段五** | 链上链下一致性 | 模拟链上事件，验证双源校验与补偿 | 7 天 | 阶段一、阶段二 |
| **阶段六** | NFT 业务服务 | 模拟 NFT 元数据拉取、稀有度计算、热度推送 | 7 天 | 阶段一 |
| **阶段七** | 回购统计服务 | 模拟回购数据，验证聚合与缓存 | 5 天 | 阶段一 |
| **阶段八** | 风控服务 | 模拟异常交易，验证实时风控识别 | 5 天 | 阶段四 |

## 验证标准定义

每个阶段的**可验证产出**需满足以下标准：

| 验证维度 | 通过标准 |
|---------|---------|
| **编译通过** | `go build` 或 `docker-compose build` 无报错 |
| **单元测试** | 核心逻辑单元测试覆盖率 ≥ 80%，全部通过 |
| **集成测试** | 提供 `test/` 目录下的集成测试脚本，一键执行 |
| **API 验证** | 提供 Postman / curl 脚本，可独立调用验证 |
| **性能基准** | 提供基准测试（Benchmark），关键指标达标 |
| **文档齐全** | 包含 README、API 文档、部署说明 |

## 技术选型一致性

各阶段统一使用以下技术栈：

| 技术 | 版本 | 用途 |
|------|------|------|
| Go | 1.22+ | 开发语言 |
| PostgreSQL | 15+ | 关系型数据库 |
| Redis | 7+ | 缓存/会话 |
| RocketMQ | 5.0+ | 消息队列 |
| Nacos | 2.2+ | 配置/注册中心 |
| Docker | 24+ | 容器化 |
| Docker Compose | 2.20+ | 本地编排 |
